# GUI architecture

_Moved verbatim out of `CLAUDE.md` on 2026-11-01 to keep that file short. Same rules, same text; `CLAUDE.md` links here._


20 custom components in `src/gui/`, all in `namespace sr`:

- **ColourPalette.h** — 28 inline colour constants (dark theme), incl. the `knobBody`/`knobFace`/`knobTick` ramp. Text tiers hold ≥4.5:1 against `panel`; `muted` (3.5:1) is decoration only, never a glyph
- **FontData.h/.cpp** — The one UI typeface, **Oxanium** (Regular + Bold, SIL OFL; replaced Space Mono 2026-10-30, owner's pick of ten candidates), embedded via BinaryData and drawn through `Fonts::ui(size, bold)`. It is **proportional**, not monospaced, so lay text out against measured widths, not character counts. `previewUIFont()` lets `sr_editor_snapshot font=` render the editor in another face to compare candidates. Plus the `Fonts::Sizes` type scale (micro 9 / small 10 / body 11 / value 12.5 / title 14 / hero 22). No bare numeric font sizes anywhere in `src/gui/` — tune type from that one block. Note these are JUCE font *heights* (ascent+descent), which render ~25% smaller than the same number in CSS px
- **LookAndFeel.h/.cpp** — `SilentRiotLookAndFeel`. Owns `drawRotarySlider` — the arc knob paint routine (five uniform ticks, value arc, body + face circles, indicator triangle inside the face). Every dimension is a ratio of `D = jmin(w,h)`, so one routine covers all knob sizes and `setScale` does not touch the graphic. A slider with the `kPointerKnobProperty` property (the amp row's GAIN/SHAPE/VOLUME and all 14 EFFECTS knobs) gets a satin pointer knob instead of the body/face/triangle: a black skirt with a chamfered bar and cream line, rotated point by point so the light stays fixed; ticks and value arc are shared. An int `kKnobWearProperty` (a non-zero seed; the editor gives each of the 17 pointer knobs its own) adds handling wear in the knob's own frame, so it turns with the knob while the light stays fixed: an ivory-aged pointer line fading toward the tip, grip-polished bar edges, rim nicks, a rubbed skirt sheen, hairline scratches and dust in the bar's crevice. No chips in the line: at real knob sizes they fall under a pixel and read as a dashed line. `kRotaryStartAngle`/`kRotaryEndAngle` (225°→495°) define the 270° sweep — a slider painted with this LookAndFeel **must** call `setRotaryParameters()` with them, or its ticks won't line up with its value
- **NotchKnob.h/.cpp** — Rotary knob shell: owns the slider, reserves the readout + label strip and centres a square knob in what's left, paints the value readout and parameter label. The knob face itself is painted by the LookAndFeel. **No focus indicator is drawn** — the knobs stay in the tab order and respond to arrow/PageUp keys, but focus is deliberately invisible (removed 2026-08-16 by request); don't reintroduce a ring without asking. Name is historical — the knob was a segmented arc with a notch pointer before the arc design. `setScale()` scales only the text strip (each metric floored at 14px — text stops being readable long before the knob does — and the parameter name keeps its full `body` size at any scale); `stripHeight(scale, engraved)` is the same arithmetic as a constexpr, for layouts to static_assert against; `preferredHeight` (112px) is the room a scale-1.0 knob needs, and laying one out shorter clips the name. Optional `setValueFormatter()` overrides the default 0–10 readout (used for DELAY TIME's ms and the `%` knobs). `setEngravedReadout()` (amp row and EFFECTS) prints the value as plain text on the panel instead of a boxed readout, `kEngravedSaving` (4px) shorter
- **VUMeter.h/.cpp** — 24-segment LED bar, 60Hz timer, green/yellow/red zones. `setLevel()` takes linear RMS and draws it on a dB scale, −60…0 dBFS across the bar (`barPositionFromAmplitude()`, pinned in `gui_vu_meter_tests.cpp`); the zones sit at 70% (≈ −18 dBFS) and 85% (≈ −9 dBFS). It was linear and a −18 dBFS DI lit 3 of 24 segments
- **ToggleSwitch.h/.cpp** — toggle wrapping `juce::ToggleButton` for APVTS attachment, in two styles: `Style::Switch` (a short satin-black bat toggle — nut, lever and ball tip all black, with dim edge highlights — through a hex nut on a narrow glass ring lit softly in the switch colour (orange on all three, so the faceplate has one accent colour), lever up = on; used by the amp row) and `Style::Jewel` (a small glass jewel in a knurled chrome bezel — `AmpFaceplate::paintLamp` at lens radius 4.5 with its glow cut to 12px — lit in the switch colour, label to its *left*; the lamp hugs the component's right edge, so a row of them right-aligns on the lamps; used by the effects cards). To set one from saved state use `setOnSilently()`: the button's `setToggleState(…, dontSendNotification)` sends no state message, so the lever/lamp would never animate to the new state. **Always lay one out against `ToggleSwitch::minHeight(style)`** — 48px for Switch (drawn at `kBatScale` 1.15 about the nut), 24px for Jewel (the glow's diameter). Switch paints its label at the top and its lever *below*, and JUCE clips paint() to the component's own bounds, so a toggle given only enough height for its label loses the track entirely: the control renders as a dead text label while its clicks keep working and the parameter keeps changing. That silent failure is what made the old flat-bar effects toggles look broken (fixed 2026-08-16); `EffectsPanel` now static_asserts its card metrics against `minHeight`
- **HeaderBar.h/.cpp** — Brand + PresetSelector + gear icon
- **TunerBar.h/.cpp** — Always-visible live tuner strip (note name + octave, cents meter, freq readout). Owns a `PitchDetector`, pulls DI windows from the processor's capture ring on the shared 30Hz timer
- **FooterBar.h/.cpp** — OS factor, latency, sample rate, bit depth
- **SectionBar.h/.cpp** — Clickable expand/collapse bar with chevron + hint text
- **AdvancedPanel.h/.cpp** — PSU supply rails (teal gradient bars) + engine state readout
- **PresetSelector.h/.cpp** — `[◂ | name | ▸]` cyclic preset browser
- **SegmentedSelector.h/.cpp** — Row of mutually-exclusive buttons
- **SettingsPanel.h/.cpp** — Overlay (560px, two columns: DISPLAY | METERS & KNOBS, then ABOUT), centred below the header over a dimmed backdrop, inside the scaled content area, so it follows the UI scale; in the standalone, an AUDIO INPUT section on top (`attachInputSelector()`, height `panelHeight()` — position the overlay with that, not `panelH`). Every rectangle comes from `layout()`, which `paint()` and `resized()` both read — don't add hand-kept y offsets again. Toggles are `Style::Jewel` with `setShowLabel(false)` (the panel paints row labels). Closes on its ✕, Escape or a click outside (editor `setSettingsOpen()`); the window grows while the panel needs more room (`getWindowHeight()`), and a static_assert keeps the plugin's panel inside the smallest window
- **InputSelector.h/.cpp** — standalone-only INPUT list. The amp reads bus channel 0 only and JUCE's standalone dialog offers inputs as stereo pairs, so the second input of a pair was never heard. Picking an input reopens the device with **only that input active** (`selectSingleInput()`); JUCE packs active inputs, so it arrives on channel 0 — no processor change. The choice lives in the device setup, which `StandalonePluginHolder` saves (`audioSetup`) and restores; it is not a parameter. `src/StandaloneDevice.*` (`standaloneDeviceManager()`) is the one place that includes JUCE's standalone window header: `nullptr` in VST3, the tools and the tests, so the section never shows there
- **IRLoaderPanel.h/.cpp** — Two views behind a `CAB | LIBRARY` `SegmentedSelector` (top right; the editor persists it as the `irView` property, default CAB). **CAB**: a `CabinetView` plus a LOAD IR chip, in front of a brick wall: a photo the owner supplied, `resources/textures/brick-wall.jpg` (BinaryData, `renderBrickWall()` scales it to cover the panel, centred), dimmed to half and vignetted on a dark palette, washed pale on a light one, and quietened under the header and the cab's name lines so small type stays legible. It is cached at the full `panelHeight` and drawn from the top, so the section's open/close animation, which resizes the panel every frame, only blits it; LIBRARY keeps the plain panel; its arrows call `stepIR()`, which cycles IR_INDEX 0 (built-in cab) → each loaded IR → wrap, and reports through `onIRSelected` — the editor maps 0 to `selectBuiltInCab()` (sets IR_INDEX 0 and applies it at once, like `selectUserIR`). **LIBRARY**: scrollable IR list, waveform display, drop zone. Drag-and-drop works in both (category tabs per UI spec §5.7 not yet implemented — user-IR-only today). The section sits directly under the amp: `layoutContent()` stacks IR LOADER → EFFECTS → ADVANCED, and the hand-set Tab order (`irSectionBar` 8, `fxSectionBar` 9, effects controls 10–28, `advSectionBar` 29) follows it
- **CabinetView.h/.cpp** — the CAB view: a 2x12 cab front painted in code (`paintCabinet()`: pebbled levant tolex — `renderTolex()`, a domain-warped cellular grain shaded as a height field with a semi-gloss highlight, grime in the creases, rubbed edges and scuffs, and wear and tear: three ragged tears to plywood, edges rubbed through to the backing, two dents — dust and rust on the grille steel (`renderGrilleDust()`, clipped to the steel so the openings stay dark), a torn-out stretch of piping with a loose end, scuffed caps; plain black corner caps (owner prefers them simple), orange accent piping, a black expanded-metal grille — staggered diamond openings filled even-odd — over two speakers that show through. Grille, baffle, speakers and caps are fixed black in both themes, like the real parts; only the tolex and piping follow the theme), at `kCabAspect` 2:1 (a little wider than a real 2x12's 3:2; trim scales with the cab's *height*, and the two speakers sit side by side in the middle, so a wider box still reads as a 2x12), round drawn arrow buttons either side of it, the playing name + detail line under it. The whole front is rendered once into `cabCache`, keyed on size, physical pixel scale and a theme token, so hovering an arrow only blits it (`kCacheMargin` covers the shadow and cap overhang); the damage is placed in units of the frame band, so it holds at any size. `setDrive(level, heat)` (the editor timer, via `IRLoaderPanel`) lights the piping: on a dark palette a soft halo — the bead's stroke Gaussian-blurred once (three box blurs) into a cached alpha mask (`glowMask`, keyed on cab size and pixel scale), tinted and blitted per frame, peak alpha `kCabHaloAlpha` 0.5, gone by 9 px — plus a pale core on the bead; on a light one a tinted bead only. Brightness is `level^0.75`. The torn-out stretch is cut before the blur, so the glow tapers into it. Don't go back to stacked strokes: they banded visibly (owner: "too much and not smooth"). Display only — `onStep(±1)` goes to the panel
- **IRWaveformDisplay.h/.cpp** — Waveform plot with envelope fill
- **EffectsPanel.h/.cpp** — 2×2 card grid (UTILITY / BOOST / DELAY / REVERB), in the faceplate's hardware style: each card is an `AmpFaceplate::paintPlate` panel, the knobs are the amp row's pointer knobs at `setScale(0.7)` (name on top, engraved value, 70×80px), and each card's ON is a `Style::Jewel` toggle beside its title. DELAY's **SYNC** and **PP** are the amp row's `Style::Switch` bat toggles, stacked SYNC over PP down the card's left before TIME; that stack (2 × `minHeight(Switch)`) is the tallest thing in any card and sets `kCardH` (136, `panelHeight` 304) — every card shares it so the knob rows stay level. DELAY has no division row: **SYNC** turns its TIME knob into the division selector — `DelayTimeAttachment` (`PluginEditor.h`) binds the one knob to `DELAY_TIME` with SYNC off and to `DELAY_SYNC_DIV` with it on (one detent per division, `syncDivisionFromKnob()` in `TempoSync.h`; MANUAL, index 0, *is* SYNC off), and keeps the last division in the `delayLastSyncDiv` state property. The parameters are unchanged, so sessions and automation still load. The card metrics static_assert against `NotchKnob::stripHeight`, `ToggleSwitch::minHeight` and `panelHeight`
- **AmpFaceplate.h/.cpp** — the amp head's front panel behind GAIN/SHAPE/VOLUME: `paintPlate()` (raised gradient, grille-cloth weave, piping — the EFFECTS cards' plate; the amp plate draws the same face without the weave, as its powder coat is its surface), corner screws, and the glass pilot lamp `paintLamp()` (shared with the jewel toggles; `bloom` sets its glow radius). It carries live state: `setDrive(level, heat)` widens the lamp's bloom; brightness stays `powered`. The piping glow it used to paint moved to `CabinetView`; it keeps the shared `glowBeadColour()` (pure, tested in `glow_colour_tests.cpp`: hue `accent`→`red` with heat) and `glowUsesHalo()` (halo on a dark palette, tinted bead on a light one, from `Colours::panel`'s luminance). Nothing glows in `paintPlate()`, so the EFFECTS cards cannot light. The amp plate alone (not the cards) gets `paintGrunge()`, a worn powder coat: a fine stipple shaded as a height field under the top light, grime in its pores and in patches, polished patches, rim dirt with soft chips to bare steel mostly at the corners, and a few hairline scratches; a light palette gets the dark marks at 40% (`ink`), as they read far heavier on white. Over that, `paintSteelLayer()` lays a photo of scratched, rust-streaked steel the owner supplied (`resources/textures/faceplate-steel.jpg`, BinaryData) as a layer, not opaque: each pixel's opacity follows how far it stands out from its local mean, so the flat steel only tints the coat while scratches, the rust streak and specks come through. The whole layer is drawn almost transparent (`kSteelOpacityDark` 0.2, `kSteelOpacityLight` 0.14; owner's call: it was too obvious at full strength). The static plate (gradient, piping, grunge, steel layer, screws) is cached in an `Image` keyed on size, physical pixel scale and a theme token (`Colours::panel.getARGB()`) — `applySettings()` swaps the palette with no per-component notice, so a size-only key would serve a stale theme
- **ProceduralTexture.h** — header-only noise for the textures painted in code (`namespace sr::texture`): `hash`, gradient noise, `fbm` (each octave rotated, so nothing lines up with the pixel grid), cellular `f1`/`f2`, `smoothstep`, and `Px`, a premultiplied pixel composited "over". Deterministic, so a cached texture is the same on every launch; GUI thread only, never for DSP. Every surface built on it blends through smoothstep, never a hard threshold — a hard cut drew a visible box on the first plate texture

**Window strategy**: The window is sized to its content height (`kWindowW` 700 × `getContentHeight()`, times the UI scale) on every platform. `applyShapeMask()` — the name is historical — runs each animation frame and calls `setSize()` whenever the animated panel heights change; the size guard makes the steady state a no-op. The old approach (a max-height window clipped with the X11 Shape Extension) is gone: the compositor used the true window geometry for move constraints, so a window taller than the screen got pinned to the top edge and could not be dragged. Sizing to content does **not** clamp to the display work area, so tall panel combinations can still exceed the screen. On Linux the editor still keeps one cached X11 connection (`getX11Display()`) for `setWindowBackground()` and the compositor bypass.

**Live tuner**: `src/dsp/analysis/PitchDetector.h/.cpp` (pure C++, MPM/NSDF) tracks the DI fundamental. The audio thread writes raw channel-0 input into a lock-free ring (`SilentRiotProcessor::pushTunerSamples`) **before** the power-off early-return, so tuning works with the amp silenced; `TunerBar` pulls the latest window via `readLatestTunerSamples` on the editor timer and runs detection off the audio thread. Detection ≥ ±5¢ accuracy on open strings (verified in `pitch_detector_tests.cpp`).

**Editor timer** (30Hz): Polls atomic level meters (real input/output RMS + grid current), DSP readout for advanced panel, footer stats, and refreshes the live tuner. The input/output level meters now read **post-trim** — after the INPUT/OUTPUT gain-staging knobs are applied. Every path that leaves `processBlock` early publishes its own meter values (review S6): tuner mute → output 0, input still live (the tuner is using it); power off → both 0; host bypass → the dry passthrough on both. It also drives the faceplate glow through `GlowDriveFollower` (`AmpFaceplate.h`), on each frame's measured length (clamped at 0.1 s): **level** is `outputPeakForGUI` mapped −48…−6 dBFS → 0…1, then eased (60 ms up, 120 ms down, on top of the audio-side peak release; snaps to 0 under 0.004 on silence) so pick attacks and 30 Hz steps don't flicker; **heat** is compression — out/in RMS (input gated at −50 dBFS) against a peak-held clean ratio that releases 0.5 dB/s on playing frames and is re-learnt whenever `glowParamsSignature()` changes (GAIN, VOLUME, OUTPUT trim, 7W, CAB, IR_INDEX, BOOST/DELAY/REVERB on, gate/width engaged) — mapped 1…12 dB → 0…1, then eased (150 ms up, 600 ms down). Power off resets it and sets `setDrive(0, 0)`. `runTimerFrameForTest(dt)` runs one frame for tests. Drives animated section expand/collapse (28px/frame linear steps). SectionBar chevrons animate at 300ms, gear icon at 400ms, toggle lever at ~200ms.

**Keyboard**: Arrow keys ±0.1 display (±0.01 internal), PageUp/Down ±1.0 display (±0.1 internal) via `NotchKnob::KnobSlider` override — or one interval, when the slider's is coarser (synced DELAY TIME steps a division). Tab order: GAIN→SHAPE→VOLUME→7W→CAB→PWR.

**UI state persistence**: Panel open states, theme, meter ballistics, knob mode, and UI scale stored as properties on `apvts.state` ValueTree — automatically saved/restored with plugin state.
