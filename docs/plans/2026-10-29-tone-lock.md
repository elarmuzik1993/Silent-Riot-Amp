# Tone Lock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Freeze Silent Riot's sound as of `main` 059b209: any later change that moves the
steady-state rendered output of the amp, cab or effects fails `verify.sh`, unless the owner
approves a new reference.

**Architecture:** A test renders a fixed matrix of settings through the real `processBlock`
(`tests/processor_harness.h`) and reduces each render to a **fingerprint**: per-frame band
levels (2048-point frames, hop 1024, 32 log-spaced bands 40 Hz–16 kHz, stereo) plus the
overall RMS, after skipping the first 0.5 s (startup is a transition, and glitch fixes stay
allowed). Fingerprints of the frozen sound are committed under `tests/tone/golden/` and every
run compares against them within a tight tolerance. Fingerprints, not raw `.f32` renders
(`tools/README.md` "How this becomes the golden lock"): ~10 KB each instead of ~750 KB, and
they tolerate float rounding between compilers while still catching a 0.1 dB change. Setting
`SR_TONE_LOCK_WRITE=1` rewrites the references; that is the only way to move the lock.

**Tech Stack:** C++17, JUCE 7 (`juce::dsp::FFT` via the SharedCode target), Catch2 v3.

**Spec:** owner decisions, 2026-10-29 session: freeze **amp + cab + effects**; cancel the
amp re-calibration, **keep the E3 aliasing fix allowed** (owner A/Bs it before the reference
moves); lock **steady-state sound**, allow glitch/transition fixes.

## Global Constraints

- The branch changes no DSP: `src/` is untouched, so the references capture 059b209's sound.
- References are written once, from this branch, before any other change.
- The lock runs in `SilentRiotProcessorTests` (so in `verify.sh` and ctest), in parallel-
  friendly test cases; total added test time stays under ~60 s.
- Moving the lock needs the owner's explicit OK, an A/B, and a new `tone-vN` tag (rule
  written into AGENTS.md).
- No AI attribution; commit as the noreply identity in STATE.md.

## Review Focus

1. **A lock that never fails is worse than none.** A sensitivity test must show that a small
   change (OUTPUT trim +0.1 dB, SHAPE ±0.02) fails the comparison.
2. **Missing or truncated reference file** must fail the test (never silently pass or
   self-write outside `SR_TONE_LOCK_WRITE=1`).
3. **Determinism:** two renders of the same case in one run must fingerprint identically.
4. **Silent bands** (energy near the noise floor) must not make the lock flaky: bands below
   the floor are compared only for "still below floor ±tolerance".
5. **Cross-platform:** references come from MSVC/Windows; Linux/GCC (CI) is unverified until
   CI runs again. Recorded in STATE.md Next.

**Interfaces (produces):**
- `struct Fingerprint { int frames = 0; int bands = 0; float rmsDb = -200.0f; std::vector<float> levelsDb; }`
  (`levelsDb` is `frames * bands * 2` channels, frame-major).
- `Fingerprint fingerprint(const std::vector<float>& left, const std::vector<float>& right, double sampleRate, double skipSeconds = 0.5)`
- `bool writeFingerprint(const juce::File&, const Fingerprint&)`; `std::optional<Fingerprint> readFingerprint(const juce::File&)`
  (binary: magic `SRTL`, version 1, frames, bands, rmsDb, then the floats).
- `struct Comparison { bool matches; float worstBandDeltaDb; float rmsDeltaDb; juce::String where; }`
- `Comparison compare(const Fingerprint& ref, const Fingerprint& got, float bandTolDb = 0.1f, float rmsTolDb = 0.02f, float floorDb = -100.0f)`
